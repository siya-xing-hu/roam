# 足迹第一版设计

日期：2026-09-22
状态：第一版已实现

## 1. 背景与目标

足迹是一个个人使用的纯前端静态地图项目。它不使用道路、商店、建筑、交通或在线瓦片底图，只展示两类信息：

1. 全国省、市、区县三级行政区划边界；
2. 本地结构化景点数据。

第一版的景点范围为江浙沪官方 A 级旅游景区。应用运行时不访问文旅部门或地图服务接口，所有边界和景点数据均作为静态资源随项目发布。

项目通过本地静态服务器运行，构建产物可以部署在任意静态文件服务器上。第一版不要求将所有代码和数据合并成单个 HTML 文件。

## 2. 第一版范围

### 2.1 包含

- 全国省、市、区县三级行政区划数据；
- 无瓦片的纯矢量行政边界地图；
- 地图缩放、平移和行政区域点击；
- 根据视野层级显示省、市或区县边界及名称；
- 江浙沪 A 级景区点位；
- 0–9 景点等级与中文标签；
- 根据等级和当前视野控制景点显示；
- 点击景点查看名称、等级、标签、地址、所属行政区和数据来源；
- 当前区域或视野内的景点列表；
- 桌面端和移动端响应式布局；
- 独立的一次性景点资源生成工具。

### 2.2 不包含

- 道路、商户、建筑、公交、地铁或在线地图瓦片；
- 路线规划和导航；
- 后端服务、数据库和在线增量更新；
- 登录、收藏、评论和用户画像；
- 景点图片、门票、开放时间和实时运营信息；
- 运行时调用高德、文旅部门或其他第三方数据接口；
- 第一版自动产生 6–9 级人工精选数据。

## 3. 技术路线

第一版采用 Vite、TypeScript 和 ECharts，不引入 React 或 Vue。

选择理由：

- ECharts 的 `geo` 与 `scatter` 能直接覆盖纯行政边界和景点点位需求；
- 不依赖在线瓦片或互联网地图 SDK；
- TypeScript 为数据格式和模块接口提供约束；
- Vite 可将依赖打包为完全静态的构建产物；
- 无框架方案能保持代码和运行时体积较小。

MapLibre 加矢量瓦片虽然更适合更大规模数据，但会引入瓦片生成和样式管理系统；Leaflet 更偏向传统瓦片地图。这两种方案均不作为第一版实现。

## 4. 系统架构

系统由前端应用、静态行政边界资源、静态景点资源以及独立数据生成工具组成。

```text
官方文旅页面/附件 ──> 一次性景点生成工具 ──> attractions.json
                                                │
行政边界静态资源 ───────────────────────────────┼──> 前端地图应用
                                                │
ECharts + TypeScript ──────────────────────────┘
```

### 4.1 前端模块

- `MapView`：创建 ECharts 实例，维护地图视野，转发缩放、平移和点击事件。
- `BoundaryRepository`：读取、合并并缓存 GeoJSON 边界文件。
- `BoundaryLevelController`：根据缩放级别和可见范围选择省、市或区县边界。
- `AttractionStore`：读取景点文件，提供按范围、等级和行政区筛选的查询接口。
- `AttractionLayer`：将景点转换为 ECharts 散点系列，控制点位大小、颜色和标签。
- `RegionPanel`：展示当前区域、景点数量和景点列表。
- `AttractionDetails`：展示选中景点详情。
- `Legend`：解释行政层级、等级颜色和当前显示阈值。

模块之间通过明确的数据对象和事件通信。ECharts 配置只由地图表现层生成，数据读取与业务筛选不依赖 ECharts。

## 5. 行政边界数据设计

行政边界采用 GCJ-02 坐标系的 GeoJSON，与景点生成器得到的高德地理编码坐标保持一致。

### 5.1 分层资源

- `provinces.geojson`：全国省级边界，用于首次加载和全国视野；
- `cities/{provinceAdcode}.geojson`：某省全部地级市边界；
- `counties/{cityAdcode}.geojson`：某市全部区县边界；
- `index.json`：记录行政编码、名称、父级编码、层级、数据路径和外包围盒。

所有数据均随构建产物发布。所谓“加载”只是在本地静态文件之间按需读取，不调用远程地图接口。

### 5.2 层级选择

地图初始显示全国省级边界。`BoundaryLevelController` 根据当前缩放级别选择层级：

- 全国视野显示省级边界；
- 省级视野显示可见省份内的市级边界；
- 市级及更近视野显示可见城市内的区县边界。

`index.json` 的外包围盒用于判断哪些父级区域与当前视野相交。所需文件在首次使用时加载，并通过有限容量的内存缓存复用。点击行政区域可以直接缩放到该区域；缩小地图会自动回到上一级边界。

具体缩放阈值作为显示配置集中管理，并在真实数据接入后通过视觉和性能测试确定，不散落在组件代码中。

### 5.3 边界简化

用于浏览的 GeoJSON 在提交前进行坐标精度压缩和几何简化，同时保留未简化来源和处理说明。简化必须避免明显的区县裂缝、自交和岛屿丢失。边界资源版本、坐标系和来源记录在 `public/data/boundaries/README.md` 中。

## 6. 景点等级与标签

景点等级字段 `level` 为 0–9 的整数：

| 等级 | 含义 | 自动生成规则 |
|---|---|---|
| 9 | 最高人工精选 | 不自动产生 |
| 6–8 | 人工精选 | 不自动产生 |
| 5 | 官方 5A 景区 | 5A 自动映射 |
| 4 | 官方 4A 景区 | 4A 自动映射 |
| 3 | 官方 3A 景区 | 3A 自动映射 |
| 2 | 官方 2A 景区 | 2A 自动映射 |
| 1 | 官方 1A 景区 | 1A 自动映射 |
| 0 | 未评级 | 无官方 A 级对应时使用 |

官方等级同时写入 `tags`，例如 5A 景区自动产生 `level: 5` 和 `tags: ["5A"]`。人工将景点提升到 6–9 时，原始 A 级标签继续保留，并将 `levelSource` 设置为 `manual`。

第一版生成器只根据官方来源自动生成 1–5 级。`overrides.json` 为未来的人工等级和附加标签预留，不要求第一版提供编辑界面。

## 7. 景点数据格式

`attractions.json` 顶层包含数据集元信息和景点数组：

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-09-22T00:00:00.000Z",
  "coordSystem": "GCJ-02",
  "coverage": ["上海市", "江苏省", "浙江省"],
  "items": []
}
```

景点记录格式：

```json
{
  "id": "sh-310115-shanghai-wild-animal-park",
  "name": "上海野生动物园",
  "province": "上海市",
  "city": "上海市",
  "district": "浦东新区",
  "adcode": "310115",
  "address": "浦东新区南六公路178号",
  "lng": 121.721,
  "lat": 31.055,
  "level": 5,
  "levelSource": "official",
  "tags": ["5A"],
  "source": {
    "name": "上海市文化和旅游局",
    "url": "https://whlyj.sh.gov.cn/5ajjq/20191008/0022-29706.html",
    "publishedAt": "2025-01-03"
  }
}
```

行政编码使用字符串，避免把标识符误当作可计算数字。ID 必须跨重复生成保持稳定，不能依赖抓取顺序。

## 8. 一次性景点资源生成工具

生成工具与应用隔离，但随仓库提交以保证数据可追溯和可重建。它执行以下步骤：

1. 从上海、江苏和浙江文旅部门的官方 HTML、JSON、CSV 或附件读取名录；
2. 保存本次来源元信息；
3. 将名称、地址、等级和行政区字段标准化；
4. 合并重复记录并生成稳定 ID；
5. 将官方 1A–5A 映射为数字等级并生成对应中文标签；
6. 使用高德地理编码 API 按官方地址补充 GCJ-02 坐标；
7. 缓存地理编码结果，避免重复调用；
8. 应用可选的 `overrides.json`；
9. 校验全部记录；
10. 原子写入 `public/data/attractions.json` 和生成报告。

高德 Key 通过专用于此工具的环境变量传入，禁止写入代码、缓存或最终数据文件。生成器不是前端构建流程的一部分。

### 8.1 生成校验

- ID 唯一且稳定；
- `level` 是 0–9 的整数；
- 官方 A 级与 1–5 数字等级映射一致；
- 官方 A 级标签存在且没有被人工等级覆盖删除；
- `adcode` 是合法的六位字符串；
- 坐标是有效数字并位于中国合理经纬度范围内；
- 坐标应落在声明行政区内，边界附近的例外进入人工复核报告；
- 来源名称、URL 和发布日期完整；
- 空名称、重复项、地理编码失败项和页面结构变化必须进入报告。

存在阻断性错误时，生成器返回非零退出码，不覆盖上一版可用数据。临时文件成功校验后再原子替换最终文件。

## 9. 页面布局与交互

页面以全屏地图为主体：

- 左上角展示项目名称、当前行政区域和返回上级操作；
- 左下角展示等级图例、行政层级和当前可见景点数量；
- 右侧展示当前视野或当前行政区域的景点列表，并允许收起；
- 景点详情以地图弹层或侧栏详情区展示；
- 移动端将右侧列表改为底部抽屉。

### 9.1 景点显示规则

- 全国视野显示 `level >= 5` 的景点；
- 省级视野显示 `level >= 4` 的景点；
- 市级、区县级视野显示全部景点；
- 6–9 级景点在所有视野层级均显示；
- 低层级被隐藏时，图例明确显示当前阈值；
- 景点大小和颜色由 `level` 决定；
- 景点名称只在较近视野或选中状态显示，以避免遮挡。

地图缩放或平移后，应用根据当前经纬度外包围盒重新计算可见景点。江浙沪之外的区域明确显示“当前景点数据尚未收录”，避免将空白误解为没有景点。

### 9.2 景点详情

详情至少包含：

- 景点名称；
- 地图等级；
- 官方 A 级标签；
- 地址与所属省、市、区县；
- 数据来源名称；
- 来源页面链接；
- 数据生成时间。

## 10. 状态与错误处理

- 省级边界加载失败：显示阻断性错误和重试操作；
- 下级边界加载失败：保留当前上级边界，显示非阻断提示并允许重试；
- 景点数据加载失败：行政地图继续可用，侧栏显示数据错误；
- 单条景点记录异常：开发和测试阶段由校验阻止构建，运行时仍进行防御性过滤；
- 当前区域未收录：显示覆盖范围提示，不显示“零景点”；
- 当前区域已收录但筛选结果为空：显示“当前视野暂无符合显示条件的景点”；
- ECharts 容器尺寸变化：使用 `ResizeObserver` 调整地图尺寸；
- 快速缩放和平移触发的更新进行节流，并忽略过期加载结果。

## 11. 性能策略

- 首次只加载省级边界和景点数据；
- 市、区县边界按当前视野加载；
- GeoJSON 在提交前简化并压缩坐标精度；
- 同一边界文件只发起一次并发请求；
- 使用有限容量缓存避免长时间浏览后无限增长；
- 景点按视野外包围盒和等级先筛选，再转换为 ECharts 数据；
- 地图事件使用 `requestAnimationFrame` 或短延迟节流更新；
- 详情和列表不重复持有完整边界几何。

验收时使用实际边界数据在桌面和中等性能移动设备上测试。全国视图首次可交互、连续缩放和平移均不得出现持续冻结；具体文件大小和耗时预算在首次数据构建后记录为基线并加入项目 README。

### 12.3 端到端与构建验证

## 13. 第一版验收标准

1. 打开项目后显示全国省级行政边界，不显示道路、商店或其他底图元素；
2. 可以缩放、平移并查看全国任意省、市、区县边界；
3. 行政区域名称随层级正确切换；
4. 江浙沪官方 A 级景点以本地数据点位展示；
5. 5A 自动映射为 `level: 5` 且包含 `5A` 标签，其他 A 级同理；
6. 应用支持完整 0–9 等级，6–9 级在所有地图层级保持可见；
7. 点击景点可查看约定的完整基础信息和来源；
8. 当前视野景点列表与地图显示一致；
9. 江浙沪之外明确标识“尚未收录”，而不是误报没有景点；
10. 应用运行时不依赖任何外部网络接口；
11. 景点生成器可独立执行，但不会被前端开发或构建命令调用；
12. 自动化测试、类型检查和生产构建全部通过。

## 14. 后续演进

第一版稳定后，可按优先级考虑：

1. 增加其他省份的 A 级景区数据；
2. 通过人工覆盖使用 6–9 级和主题标签；
3. 增加名称与行政区搜索；
4. 增加非 A 级景点和景点说明；
5. 数据量显著增长时改用矢量瓦片或空间索引；
6. 增加收藏、路线或在线更新服务。

这些能力不影响第一版的静态数据接口和核心模块边界。
