# 景点数据采集与地图数据整合

日期：2026-09-23

## 文件职责

每个来源保存自己的数据，使用稳定的景点 ID 关联；地图展示字段由最后一个脚本统一生成。

| 脚本 | 输入 | 输出 |
| --- | --- | --- |
| fetch_mct.py | 文旅部公开数据 | tmp/01-文旅部景点数据.json |
| geocode_amap.py | 景点基本资料 | tmp/02-高德原始数据.json |
| build_map_data.py | 基本资料、高德原始数据 | public/data/attractions.json |

文旅部采集报告用于查看数量和待确认项。高德原始文件本身承担断点记录，不再另外维护只有坐标的缓存或混合了基础资料的阶段文件。

## 文旅部基本资料

采集全国 5A 景区和世界文化遗产，保留名称、分类、评定年份、地区、介绍、图片链接和官方来源。

每条记录包含稳定 ID、可编辑的查询名称 geocodeQuery，以及 ready、needs_review 或 skip 状态。数据单位是实际独立游览地，一条记录只查询一个地点。已确认的同一景点合并；多地点项目根据核对后的名单拆分，遗产集合名称只作为身份关联，不另外放地图点。未能确认的对象保留 needs_review；skip 必须说明原因。

完整官方原记录保留在顶层 sourceRecords，items 通过 sourceRecordIds 关联，不用集合介绍和图片冒充子景点独立资料。拆分使用固定短标识生成稳定 ID；名称修改不影响 ID。长城等大型项目选择主要独立游览地，不以遗产保护范围内每个子项作为旅游景点。规则保存在采集脚本中，重跑结果一致。

classifications 保留来源身份，并区分 component（组成部分）、contains-component（包含遗产点）及 viewpoint（沿线观景地），避免把整个旅游区都声称为遗产本体。已核实拆分和查询名称不等于高德已确认匹配，坐标仍在后续阶段获取和校验。

列表与详情页的名称或年份差异作为 sourceDiscrepancies 保留。这个文件不写入高德响应或地图坐标。

## 高德完整原始数据

顶层 items 保存景点 ID、基础资料指纹、审核状态、匹配状态、候选和选中的地点，选中结果关联原请求 ID、候选下标及 POI ID，不复制景点简介等基础资料。requests 保留所有历史请求，包括失败和每一次重试：

- 独立请求 ID、关联景点 ID、时间和重试次数；
- 请求方法、接口地址、全部业务参数和显式请求头；
- HTTP 状态、响应头、完整正文和全部 JSON 字段；
- 请求未完成、网络失败或接口错误的状态。

Key 在参数和响应中脱敏。非 UTF-8 正文使用 Base64 保存。收到的原始内容先保存，再进行结果判断；没有筛选成坐标后丢弃其他字段的步骤。

请求发出前记录 pending，收到响应后立即原子写入。重跑时从原始响应恢复断点，复用成功、明确无结果和永久查询错误，只补未完成或临时失败的请求。响应未落盘前中断的最后一次请求，可能需要重查。

缓存指纹由接口地址、请求方法和业务参数组成，不包含 Key 或字段提取代码的版本；后续修改地图字段不会导致重新请求。更改查询名称会产生新指纹，旧请求继续保留。

先复核已有地理编码返回；名称、地区和地点级别明确的结果可以复用。无法明确匹配时使用 POI 关键词搜索，优先使用景点全名并限定已知城市，结合类型、别名和父子关系筛选。搜索分页和其他关键词的返回分别完整保存，未收齐的宽泛搜索不据此声称候选唯一。仅有城市坐标、服务设施或仍有多个合格候选时保留待确认。

请求成功数与匹配成功景点数分别统计。采集单进程执行，请求起始时间至少间隔 0.5 秒。暂时错误按 1、2、4 秒重试；权限、Key、IP 封停和全局请求错误立即停止。系统文件锁随进程退出自动释放，强制结束后可再次运行。

原始文件是长期复用的数据，即使位于 tmp 目录，也不应在需要断点恢复时删除。

## 地图数据整合

build_map_data.py 只读本地文件，不调用高德。它先按景点 ID 关联，再确认基础资料指纹一致，以免基础资料修改后误用旧查询结果。

整合时从完整原始返回重新执行同一套匹配规则，接受唯一明确的景点，并检查坐标和行政编码。基础资料未确认、响应缺失或匹配不明确时，列出具体记录并保留现有地图文件。

输出符合当前前端数据格式：

- 景点 ID、名称、经纬度、GCJ-02 坐标系；
- 省市区、行政编码、地址；
- 展示等级、标签和官方来源。

A 级对应展示等级 1–5。仅有世界遗产分类而没有 A 级时使用现有“未评级”等级 0，并保留遗产标签。正式输出仅包含成功整合且未明确跳过的记录，全部准备好后原子替换。

## 后续补充

新增数据来源时单独编写采集脚本，以景点 ID 关联，原始结果单独保存。在整合脚本中增加相应取值规则即可。

高德某次响应已包含的字段，可以直接从原始数据重新提取；该接口没有返回的字段，需要另行采集。

## 使用方式

只保留运行脚本和简短 README，不创建独立测试脚本或测试类。使用者直接运行相应脚本，检查实际产物。

基础资料确认后运行高德采集，坐标匹配完成后执行整合脚本生成地图数据。
